Getting started

Install steps differ by platform — find yours below. Everything after that (accounts, data sources, saving a roast) is the same for everyone.

Setup & run

Prebuilt binaries (beta, free for now, unsigned): Windows, macOS (Apple Silicon or Intel), and Linux (command line) builds are available at this Google Drive folder — unzip and run, no install needed. They're unsigned, so Windows/macOS will warn the first time you open one; each zip's own README explains exactly how to get past that. Skip this and use the steps below instead if you'd rather run from source.

macOS, Linux, or Windows via WSL2

cd roast-telemetry
scripts/install.sh
scripts/run-server.sh

install.sh sets everything up (once, safe to re-run). run-server.sh starts the app at http://localhost:8000. Options for both: Scripts reference below.

Windows — native PowerShell

Only needed for a real roaster's USB/COM port — WSL can't reach that. Otherwise use WSL2 above. 

cd roast-telemetry
scripts\install.ps1
scripts\run-server.ps1

If Activate.ps1 refuses to run, once: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

Raspberry Pi / headless Linux, over SSH: scripts/install.sh --yes, then scripts/run-server.sh --lan, then open http://<that machine's address>:8000 from another device. Serial roaster? Your user needs the dialout group: sudo usermod -aG dialout $USER, then log back in.

Before using --lan / -Lan: run the server on the machine the roaster is actually plugged into — other devices can only view/control an already-running roast, not reach a port on a different machine. And since this app can send real heater/fan/drum commands to a real, heat-producing machine, anyone on your network can too once --lan is on. Fine on a trusted home network; think twice anywhere else.

Accounts and access

First visit shows a login/register screen — no default account. The first person to register becomes admin with immediate access; everyone after that is pending until the admin approves them on the Manage Access page. Every allowed account, admin or not, can use everything in the app — there's no per-feature permission system beyond that one gate.

To call the API directly (a script, Home Assistant, curl) instead of logging in through the browser: click your username → Account → generate an API key, sent as an X-API-Key header. Shown once, in full — save it somewhere, since it can't be shown again.

The Live Roast screen

Laid out like a roasting-scope screen: ON/OFF and START in the toolbar, control sliders for Burner/Air/Drum beside a live BT/ET chart, a readout column, and milestone buttons (Charge, Dry End, FC Start, Drop, ...) underneath. More derived readouts (DRY%, »DRY, »FCs) are available as optional add-ons in Settings.

The data sources

Pick one from the Configure Roast form's "Connection type" dropdown:

  1. Simulator — a thermal model that generates realistic BT/ET/RoR curves and auto-detects roast events. No hardware needed.
  2. .alog Playback — replays a real roast log (this app's own, or a real-world .alog), events and notes included.
  3. Direct Modbus (USB or Ethernet) — talks to a real roaster's PLC. Built-in defaults for Coffee-Tech's FZ-94 and FZ-94 Evo; any Modbus roaster's registers are overridable. See docs/modbus/.
  4. Direct USB (thermocouple meter) — reads a Mastech MS6514 over USB-serial (read-only; T1 → BT, T2 → ET).
  5. Aillio Bullet (USB) — talks to a real Bullet over its own USB protocol. Ships with the R1 model, nothing to configure. See docs/aillio/bullet-r1.html.
  6. TC4+ (USB, aArtisanQ/PID firmware) — ASCII serial commands to a TC4+ shield. Heater/Fan control, no Drum channel, no feedback readback. DIY hardware, so no built-in preset.

Live-hardware milestones (Charge, Dry End, FC Start...) are manual clicks by default; auto-detect from BT is an opt-in alternative in Configure Roast. ON connects and streams live readings; START actually starts recording — two separate steps for real hardware, one step for simulator/alog_playback.

Saving a roast

Automatic. Click OFF when you're done, then:

  1. Click View detail, or find the roast under History.
  2. Click Download .alog at the top of the detail page.

Testing without real hardware

Pick a simulated device in the app. In Configure Roast, the port/host field has a Try a simulated one link (FZ-94, FZ-94 Evo, MS6514, TC4+) — nothing to install, on any platform. The roast is tagged simulated and left out of History's averages.

For a developer who wants a fake running on its own, or a real virtual serial port: scripts/fake-hardware.sh fz94 (or ms6514 / tc4 / evo) — see hardware_fakes/README.md for the full reference. The Aillio Bullet has no fake (it's a raw USB device) — see docs/aillio/bullet-r1.html.
