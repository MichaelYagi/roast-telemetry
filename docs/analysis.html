Comparing and analysing roasts

Every roast, whether you recorded it from a roaster or uploaded a log file, boils down to one row of numbers: temperatures and times at each milestone, phase times, rate of rise, weights, and how it turned out. Those rows are what the comparison on the History page, the Analysis page, the History totals and the downloads are all built on.

Analysing uploaded logs

Roasts uploaded from .alog files on the History page (drop them on the Import bar, or point at files on the server) are analysed exactly like roasts recorded here. What the app reads from a log:

  • The curve and milestones. Charge, Dry End, First Crack, Drop and the rest. A log that never marked Drop gets no Drop numbers, and simply has gaps in those columns.
  • Temperatures in Celsius or Fahrenheit. A log saved in °F is converted to °C on the way in, so every roast lines up.
  • The roast date. Read from the file's own timestamp, so uploaded roasts sort and filter by the date they were roasted. Roasts uploaded with older versions get their dates repaired once, the next time the server starts.
  • Weights and notes, when the file has them.

Roasts made by replaying a saved log on Live Roast just repeat that log's data, so the Analysis page leaves them out unless you choose “Replayed logs” under Data from. Roasts on a built-in simulated device are left out too, unless you tick Include simulated.

History: totals and downloads

The tiles at the top of History cover every finished roast the filters match, across all pages, not just the page of the table you're looking at. Simulated roasts are left out. Beside them:

  • Download all (.zip) — every matching roast's .alog file in an alog/ folder. A small ▸ beside it opens a choice of extra formats to include too — JSON, the roast-log CSV, Excel, PDF — each in its own folder in the same zip. Roasts with the same title get their ID added to the file name so none overwrite each other.
  • Analyse these — opens the Analysis page.

The zip follows whatever filters are set on History or Analysis.

The PDF report is built in the browser, one roast at a time (a chart image plus the same tables as the roast's own page), so it's capped at 150 roasts per zip — narrow the filters first for a larger history. The other three formats have no such limit; they're built on the server.

Comparing roasts

Comparing is done from the History page. Tick two or more roasts in the table and press Compare. A comparison panel opens at the top of History, and Close comparison puts you back to the plain list, with your ticks kept. You can compare up to 20 roasts at once.

The comparison is the ticked roasts. Tick another roast and it joins the comparison; untick one and it leaves. The ticks stay when you change page or filters. A bar above the table says how many roasts are selected, including any on other pages, next to Compare, Delete and Clear selection, so it's always clear what a delete would remove. With nothing selected, the same place has an Open a saved comparison box.

  • Curves overlaid for bean temperature, environment temperature or rate of rise. Line up on Charge (on by default) lines every curve up at its own Charge, so roasts that were recorded starting at different moments still overlay properly. Untick it to see raw roast time. Past eight roasts the line colours repeat, so the line style changes (dashed, then dotted) to keep them apart.
  • Hide from graph on a roast's row takes its line off the graph only. The roast stays ticked, and stays in the table (dimmed). Click Show on graph to bring it back.
  • One row per roast in the Numbers table, with a colour dot matching its line and the roast's name fixed on the left while you scroll sideways. The numbers are in groups: Temperatures, Timing and Phases start open, the rest (rate of rise, weights, outcome, beans) start closed. Click a group name to open or close it.
  • Sort by clicking a number's heading: smallest first, then largest first, then back to the selection order. Roasts without that number go last.
  • Baseline — choose one roast as the baseline. It moves to the top, and each other roast shows how far it is from it in each cell, for example +0:12 or −3.5.
  • Saved views keep the roasts, curve, alignment, baseline and hidden roasts under a name. It's one field: pick a saved view from the suggestions to load it, or type a name and press Save. Saving under a name that already exists updates that view.
  • The roasts being compared are kept in the page address (/history?compare=…), so a comparison survives a reload and can be bookmarked or shared. The old /compare address goes to History.
  • A roast with no saved recording (interrupted before anything was saved) has no curve to compare. It's left out with a note saying which.

Analysis

The place for questions across many roasts. Set the filters (search, beans, tag, where the data came from, date range, simulated roasts) and press Apply filters (or Enter). Nothing reloads while you're still choosing, and a note reminds you when the filters have changed but not been applied. Then choose:

  • Across (X) and Up (Y) — any two numbers, or Date to see one number over time. Each roast is a point; click a point to open that roast in a new tab.
  • Colour by — beans, origin, process, tag, month, who roasted it, or where the data came from.

Below the chart:

  • How consistent — for each group, the average and the spread (standard deviation) of the numbers that matter most for repeatability, plus your chosen Y. A smaller spread means more repeatable roasts. A group with a single roast has no spread.
  • Roasts that stand out — roasts more than two standard deviations from the rest of their group on the chosen Y, for groups of five or more roasts.
  • Saved views — keep the filters, both axes and the grouping under a name, the same one-field way as in a comparison.
  • Download all — the same zip as History, for the current filters.

Only finished roasts count. If more than 2000 match, the newest 2000 are used. With few roasts the averages and spreads mean little, so treat them as tentative.

Asking the AI

If a local Ollama server is set up (a URL and a model under Settings → AI Roast Review), an Ask the AI panel appears on the Analysis page. It sends the model this page's summary numbers (per-group averages and spreads, and the twenty most recent roasts' key figures), never whole curves, plus an optional question you type, and shows what it makes of them. It follows the current filters and grouping. Nothing leaves your network unless your Ollama URL points elsewhere. Without Ollama configured the panel simply isn't shown.

A local model can take a minute or two; the page waits and shows the answer when it arrives. The request asks for an 8192-token context window so the summary isn't cut off. AI comments can be wrong, so check them against the numbers on the page.

How it turned out

On a roast's own page, How it turned out records what the roast was like once you've tasted it: colour (Agtron), a cupping score (0–100), a rating (1–5 stars) and tasting notes. They become numbers you can compare, chart and group, and columns in every downloaded format. They are saved in the app's database, not in the roast's .alog file.

Beans

A roast has one Beans field, on its own page and when configuring it on Live Roast. Type any name, or pick from your saved beans as you type. A name that matches a saved beans record (ignoring capital letters) links to that record automatically, using the saved spelling. A name that isn't in the list yet is added to it automatically as a record with just that name, so the Beans page always shows every name in use. Names already typed on your roasts, and names in uploaded logs, are added the same way.

Some programs save a whole description in a log's beans field, with the line breaks and accented letters written as escape codes (for example Caturra\nEthiopia\nFarm: …\nProcess Natural…). Those are decoded and split up when the log is uploaded. The name is the first line, followed by the origin when there is one (for example Caturra · Ethiopia). The origin, process, variety, altitude and farm are filled in from the lines that say so. The whole description is kept in the record's Notes, one line each, so nothing is lost. On the roast's own page a Beans card shows those lines as they were written. Records already in your list that look like this are tidied the same way once, when the server starts, and duplicates are merged. Edit a record on the Beans page to change any of it.

The Beans page keeps the fuller record for each green bean you roast: name, origin, process, variety, altitude, density, moisture, supplier and notes. A roast linked to one can be grouped and filtered by beans, origin and process, and adds the beans' density, moisture and altitude as numbers. Deleting a record keeps the name on the roasts that used it and only removes the link (typing that name again adds it back).

API

All under /api. The filters below are the same on every analysis endpoint.

MethodPathPurpose
GET/analysis/metricsEvery number, with its label, unit and group
GET/analysis/tableOne row per finished roast with all its numbers
GET/analysis/summaryCount, mean, standard deviation, min and max per group; group_by is none, beans, origin, process, tag, month, roaster, mode or source
GET/analysis/roasts/{id}The same record for a single roast
GET/analysis/export.zipEvery matching .alog, plus formats (comma-separated: json, roastlog_csv, xlsx) for extra folders in the same zip
POST/analysis/insightsAsk the configured Ollama model to comment on the matching roasts (202; 400 if Ollama isn't set up)
GET/analysis/insights/{id}Poll a request: pending, ready (with text) or failed
PUT/roasts/{id}/outcomeColour, cupping score, rating, tasting notes. A field left out is unchanged; null clears it
PUT/roasts/{id}/beansSet the roast's beans by name: a name matching a saved record (ignoring case) links to it, any other name is added to the Beans list and linked, blank clears it
GET / POST/beansList or create saved beans
PUT / DELETE/beans/{id}Edit or delete saved beans
GET / POST/viewsList (?kind=compare or analysis) or save a named view; saving under an existing name updates it
DELETE/views/{id}Delete a saved view

Filters for the analysis endpoints: q, tag, bean_id, mode, status, created_by, created_from, created_to (a bare date means the whole day), source (recorded, uploaded or replay), include_simulated and include_replays.
